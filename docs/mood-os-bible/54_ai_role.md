# 54 — AI Role

> AI in MOOD is a quiet noticer that turns a person's small choices into gentle, human reflections — never a therapist, never a judge, never a diagnostician.

## Purpose
This chapter defines what AI is *for* inside MOOD and, just as importantly, what it must never become. AI exists to deliver the core promise: "Someone noticed something small about my life that I never knew how to say." It powers the Reflection Generator, Challenge Generator, Pattern Recognition, Memory Engine, and Copy Linter (see Ch. 56–59, 63). All of these serve one goal — making a person feel gently seen. AI is a craftsman of small human moments, not an authority on the user's psychology.

## User Experience
The user never "talks to an AI." They never see a chatbot, a typing indicator, or a persona. AI is invisible infrastructure: it writes the living Reflection under today's Moment, proposes the three Challenge levels, and occasionally surfaces a soft Pattern. Everything arrives in warm, intimate Hebrew (RTL). Example reflection: "שמנו לב שהיום בחרת ברגע קטן של שקט" ("we noticed you chose a small moment of quiet today"). The voice is a caring friend who observes, wonders, and invites — never one who assesses or prescribes.

## Game Mechanic
AI is a generation-and-guardrail layer, not a game state. Inputs: the user's `HumanMap`, recent `Attempt`s, `JournalEntry` sentiment, and the current `MomentTemplate`. Outputs: Hebrew `Reflection` copy, three `ChallengeLevel`s, and optional `Pattern` candidates. Every output passes Tone Guardrails (Ch. 62) and the Copy Linter (Ch. 63) before it can ship. Success in the game is always the *attempt*; AI copy must reinforce that and never reference outcomes, streaks, or scores.

## Screens Needed
- Today / Daily Moment (reflection + challenge copy)
- Challenge Selection
- Patterns
- Settings (AI/privacy controls)

## Visual Assets Needed
None generated by AI here — AI produces text only. Visuals come from Grok (Masterpiece, Moment, Light assets). NEVER any text baked into images; AI copy renders in the live RTL text layer.

## AI Logic
All engines use the **Claude API** (Anthropic), model `claude-opus-4-8`, with adaptive thinking. AI never diagnoses, labels, or uses clinical language. Guardrails are enforced in two layers: a system prompt that forbids banned framings (Ch. 64) and a deterministic Copy Linter that blocks banned tokens before delivery. Grok is used ONLY for visuals, never for user-facing language.

## Data Stored
- `Reflection` (Hebrew string, sourceMomentId, createdAt ISO 8601, engineVersion)
- `Challenge` with three `ChallengeLevel`s
- `Pattern` candidates (soft float signal, confidence, decay)
No raw model prompts are persisted with user identity beyond what's needed for regeneration. Local-first; optional Supabase sync.

## Edge Cases
- Offline: fall back to pre-generated/cached Hebrew copy; the daily loop never blocks.
- AI failure/timeout: serve a safe hand-authored fallback Reflection, never an error.
- Empty HumanMap (first run): use warm, universal copy that assumes nothing.
- Distress signals in Journal: hand off to User Safety (Ch. 61); AI must not counsel.

## Build Requirements
- `aiClient` wrapper around Claude API with retry, timeout, and streaming for long output.
- Guardrail middleware (Tone Guardrails + Copy Linter) on every output path.
- Deterministic fallback copy bundle shipped with the app.
- Effort: medium. Shared across all Volume 06 engines.

## Definition of Done
- [ ] Every AI output passes Tone Guardrails and Copy Linter before display.
- [ ] No user-facing chatbot, persona, or "talk to AI" surface exists.
- [ ] All user-facing AI copy renders in Hebrew RTL.
- [ ] Offline and failure paths serve safe fallback copy, never errors.
- [ ] Never-diagnose rule enforced in system prompt and linter.
