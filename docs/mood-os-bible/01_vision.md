# 01 — Vision

> MOOD is a Human Experience Game that helps one person, once a day, notice something small and true about their life and live one brave step toward it.

## Purpose
MOOD exists to give a person the feeling that "someone noticed something small about my life that I never knew how to say." It is a Human Experience Game — not a wellness app, not a journal app, not a card game, not social media. The Vision chapter fixes the north star every other volume answers to: a daily ritual that turns quiet self-noticing into a lived, real-world act, and slowly builds a living archive of a life. Every product decision downstream is judged against whether it deepens that one daily feeling.

## User Experience
The user opens MOOD once per day. They meet a single Daily Moment: a timeless artwork, a tiny title, a short living Reflection written for them, an optional invitation, and an optional Challenge at three levels — Easy, Medium, Brave. They choose one, close the app, and go live it in the real world. In the evening they return to a short Journal. Over weeks a Living Library and gentle Patterns grow. The tone is intimate, never clinical. Example title copy: "רגע קטן של אומץ" ("a small moment of courage"). Example reflection opener: "שמנו לב למשהו קטן אצלך היום" ("we noticed something small about you today").

## Game Mechanic
The Vision is expressed through the Core Loop: Discovery → Human Map → Daily Ritual → Moment → Challenge → Live → Evening Journal → Living Library → Pattern Engine → Ripple. The single hard rule of the whole game: success is defined by the attempt, never the outcome. States are per-day (unseen → seen → challenge chosen → lived → journaled) and per-life (Library and Human Map accumulating). There is no win state, no score, no streak. The only "progression" is a life becoming more visible to the person living it.

All generated by Grok, painterly-photographic, warm light, negative space, human intimacy. NEVER any text baked into an image; all copy is a live RTL text layer rendered by the app.

## AI Logic
The Vision is realized by the shared engines (see Ch. 06): Reflection Generator and Challenge Generator (Claude) produce Hebrew copy; Pattern Recognition surfaces gentle patterns; Memory Engine retrieves relevant past `Moment`s and `Attempt`s. All outputs pass Tone Guardrails and the Copy Linter. Never diagnose, never label, never shame.

## Data Stored
The Vision does not add entities; it constrains them. Core entities: `User`, `HumanMap`, `Moment`, `DailyMoment`, `Challenge`, `Attempt`, `JournalEntry`, `LibraryItem`, `Pattern`. All copy fields store Hebrew strings; timestamps ISO 8601. Local-first storage is the source of truth; Supabase is optional cloud sync.

## Edge Cases
- First run: show warmth before any data exists (see Ch. 02 tone rules).
- Skipped days: never penalized — no streak, no guilt copy.
- Offline: full loop works locally.
- Long RTL text: reflection layout must not clip.
- Safety: distress signals route to gentle, non-diagnostic support copy.

## Build Requirements
Next.js 14 App Router, TypeScript, Tailwind, mobile-first, full RTL, light/dark. Zustand state with autosave and BroadcastChannel sync. PWA installable, local-first with optional Supabase. This chapter ships as the canonical reference all volumes cite; no new endpoints.
